# Закрытый конфиг для личного тестирования

Сборка `internal` позволяет тестировать смену значка и Cover Mode без назначения
приложения Device Owner. Настоящий статус ДО и системная блокировка Bluetooth
продолжают требовать реальные права. Обычные debug/release не содержат тестового
сетевого клиента.

## 1. Отдельный приватный сервер

API сохраняет прежний адрес **https://bluetoothdisable.app/api/test-config**.
Серверный Worker, конфиг и SHA-256 разрешённых токенов находятся в приватном
служебном репозитории **Bluetooth-Disable-Internal**; настройка описана в его README.
KV для новой архитектуры не требуется. Открытый репозиторий содержит только
Android-клиент, документацию и статический сайт, без закрытого backend.

- Сайт публикует Worker `bluetoothdisable` из `docs/pages`.
- Приватный workflow отдельно публикует Worker `bluetoothdisable-internal-config`
  на **Route** `https://bluetoothdisable.app/api/test-config*`.
- Маршрут API работает поверх Custom Domain сайта. Приватный Worker не получает
  `assets`, не заменяет сайт и не привязывает к себе весь домен.
- Workflow сайта не читает KV, закрытые настройки или секреты приватного backend.
  Публикация сайта не управляет маршрутом отдельного API Worker.
- API принимает только GET и `Authorization: Bearer <43-символьный токен>`.
  Без корректного включённого токена отвечает HTTP 401, а не статическим JSON.
- Ответ для разрешённого устройства:
  `{"allowLauncherWithoutDeviceOwner":true,"validForSeconds":1209600}`.
  При выключенном флаге: `{"allowLauncherWithoutDeviceOwner":false,"validForSeconds":0}`.
- Хеш вычисляется от текстовой строки токена. Прежний ключ KV `token:<хеш>`
  совместим: в приватный список переносится только хеш после `token:`.
- Прежний APK и токен совместимы: старый клиент получает срок максимум 900 секунд.
  Internal **1.1.1-internal** (versionCode 27) отправляет заголовок
  `X-Test-Config-Lease-Version: 2` и принимает срок до 1 209 600 секунд (14 дней).
  Для длинного срока требуется установить новую internal-сборку; токен менять не нужно.
  URL, Bearer-авторизация и два поля JSON сохраняются.

Секреты `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID` для нового backend нужно
добавить в приватный репозиторий отдельно; секреты сайта остаются в этом репозитории.
Существующий namespace KV и переменная `CLOUDFLARE_TEST_CONFIG_KV_ID` новой схемой
не используются. Сервер можно развернуть до слияния этого PR.

## 2. Собрать и установить internal

```sh
./gradlew :app:assembleInternal
```

В Windows: `.\gradlew.bat :app:assembleInternal`. APK находится в
`app/build/outputs/apk/internal/app-internal.apk`. В Android Studio выбери
build variant **internal**. Android CI также собирает APK и прикладывает artifact
`bluetooth-disable-internal` к проверке PR.

- Application ID: `com.pulse.bluetoothdisable.internal`.
- Версия имеет суффикс `-internal`, обычный значок подписан `Bluetooth Disable (Internal)`.
- Сборку можно установить рядом с обычной версией. У них раздельные локальные данные,
  заметки, галерея, коды доступа и ключи Android Keystore.
- Сборка подписана debug-ключом. Для обновлений без удаления используй один и тот же
  локальный ключ. APK разных CI-запусков может иметь разные debug-подписи и потребовать
  удаления предыдущей **internal**-установки; её локальные данные при удалении потеряются.
- Только `internal` имеет разрешение `INTERNET`. У `debug` и `release` нет клиента,
  endpoint, хранилища токена или панели тестового доступа. Разрешение сети выдаётся
  Android при установке, без отдельного запроса пользователю.

Открой главный экран internal и блок **Внутреннее тестирование**, введи `token`,
нажми **Сохранить и проверить**. Поле пароля очищается после отправки. Токен хранится
зашифрованным AES-GCM с ключом Android Keystore в `noBackupFilesDir`; в резервные
копии, перенос данных, журналы и сохранённое состояние UI он не попадает.

## 3. Включать и отзывать доступ

В приватном репозитории меняй `test-config/config/launcher-test.json` и список
`test-config/config/tokens.json`, затем дождись успешной публикации. При сохранении
самого файла ещё работает предыдущая версия сервера. Для общего отключения выставь
флаг `false`, для отдельного устройства — `enabled: false` у его хеша или удали запись.
Сам исходный токен не помещай в Git, комментарии или журналы CI.
Сам токен не истекает по времени: срок относится к выданному разрешению.
Его можно отозвать серверной записью `enabled: false`.

API выдаёт только флаг и срок, без хешей и списка устройств. Все ответы имеют
`Cache-Control: private, no-store`. Разрешение в приложении живёт максимум 1 209 600 секунд (14 дней)
с начала успешного запроса, измеряется монотонными часами `elapsedRealtime` и не
продлевается при ошибке сети. При успешном ответе с выключенным флагом или HTTP
401/403 доступ снимается сразу. Уже выбранный Cover Mode и локальные данные не
сбрасываются. После завершения процесса или перезагрузки телефона нужна новая проверка;
прежняя сессия не восстанавливается. Длинный срок не сохраняется на диск. Новая версия Worker может распространяться с задержкой.

Приложение проверяет доступ при входе на главный экран и по кнопке проверки.
HTTPS использует штатную проверку сертификата; перенаправления запрещены.
Таймаут соединения/чтения — 5 секунд, максимум JSON — 4096 байт.
Запросы не выполняются из Cover Mode. Полная блокировка Bluetooth без ДО
этим разрешением не становится доступной.

## Проверки перед использованием

```sh
node --test scripts/site-api-separation.test.mjs
./gradlew :app:testDebugUnitTest :app:testInternalUnitTest :app:lintDebug :app:lintInternal :app:assembleDebug :app:assembleInternal
```

Серверные тесты и проверка реального HTTP endpoint выполняются в приватном
репозитории. CI здесь также проверяет реальные APK: `INTERNET` и тестовый клиент
есть только в internal, application ID и launcher-alias соответствуют пакету.

Ручная проверка после настройки backend:

1. Без Authorization, с неизвестным или отозванным токеном API возвращает 401.
2. С зарегистрированным токеном и выключенным флагом кнопка смены значка отсутствует.
3. После включения флага и успешного деплоя обнови доступ в уже установленном APK:
   проверь Calculator, Notes, Calendar, Gallery и возврат к обычному значку.
4. Выставь срок 15 секунд, дождись деплоя, обнови доступ и выключи сеть.
   Через 15 секунд кнопка должна скрыться, открытый диалог выбора — закрыться.
5. При отзыве и новой проверке кнопка скрывается; выбранный режим и данные сохраняются.
   Обычные debug/release по-прежнему требуют ДО для кнопки.

Успешные проверки кода не доказывают работающий деплой в Cloudflare или работу
на устройстве. Открытый код можно модифицировать; схема ограничивает чтение
серверного конфига и штатную internal-сборку. Авторизованное устройство видит свой
ответ, а скопированный токен даёт тот же доступ.
