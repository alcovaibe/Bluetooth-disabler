# Закрытый конфиг для личного тестирования

Сборка `internal` позволяет тестировать смену значка и Cover Mode без назначения
приложения Device Owner. Доступ выдаётся закрытым API Cloudflare только после
проверки вручную введённого токена. Статус Device Owner и проверки системной
блокировки Bluetooth не подменяются.

## Что находится в открытом репозитории

- Код сайта, Worker, клиента и этой инструкции.
- Адрес API: `https://bluetoothdisable.app/api/test-config`.
- Публичная заготовка `docs/pages/config/app-config.json`, которая не управляет
  тестовым доступом и не содержит закрытых значений.
- В `wrangler.jsonc` нет настоящих токенов, значений закрытого конфига или ID KV.

Настройки и хеши тестовых токенов находятся в Cloudflare KV, вне Git. Знание URL
не даёт доступа к конфигу. Неавторизованный запрос получает HTTP 401. Подпись,
`robots.txt`, необычное имя файла и CORS не заменяют проверку доступа.

## 1. Подготовить Cloudflare до слияния PR

1. В панели Cloudflare открой **Storage & Databases → KV** и создай namespace
   `BLUETOOTH_TEST_CONFIG`. Скопируй его ID из 32 шестнадцатеричных символов.
2. В GitHub открой репозиторий → **Settings → Secrets and variables → Actions →
   Variables**. Создай repository variable `CLOUDFLARE_TEST_CONFIG_KV_ID` с этим ID.
   Это идентификатор ресурса, а не пароль. Он нужен существующему workflow
   публикации, который формирует локальный `wrangler.deploy.json` с binding
   `TEST_CONFIG`. Сгенерированный файл исключён из Git.
3. Существующие secrets `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID` продолжают
   использоваться для публикации. Не копируй их в Android-приложение, KV, исходники
   или обсуждение PR. Проверь, что API token позволяет публикацию Worker с KV binding.
4. В namespace создай ключ **`launcher-test`**, значение JSON:

   ```json
   {
     "allowLauncherWithoutDeviceOwner": false,
     "validForSeconds": 900
   }
   ```

   Оставь флаг `false`, пока не подготовишь личный токен. При `true` срок должен быть
   целым числом от 1 до 900 секунд. Некорректный срок не выдаёт разрешение.
5. На своём компьютере из корня репозитория выполни:

   ```sh
   node scripts/create-test-token.mjs
   ```

   Скрипт выдаст `token`, `kvKey` и `kvValue`. Он генерирует 32 случайных байта;
   токен кодируется в 43 символа base64url. **Не публикуй вывод команды** и не
   отправляй его в Issues, PR, GitHub Actions или git. Сохрани `token` приватно.
6. В KV создай ключ с точным значением `kvKey` (`token:` и SHA-256 токена).
   Значение — JSON из `kvValue`:

   ```json
   { "enabled": true }
   ```

   Сам `token` в KV не записывай. Повтори генерацию для каждого личного устройства,
   если нужен раздельный отзыв доступа.
7. После настройки переменной и KV можно слить PR. Workflow **Deploy Cloudflare
   Site** публикует сайт и Worker. Для повторной публикации используй
   **Actions → Deploy Cloudflare Site → Run workflow**. Не запускай публикацию
   из другой ветки: текущий workflow публикует выбранный код на основной сайт.

Если переменная KV ID отсутствует или некорректна, workflow останавливается до
публикации с явным сообщением. Простая команда `wrangler deploy` использует базовый
конфиг без KV; API при этом недоступен. Для ручного деплоя из `main` задай
`CLOUDFLARE_TEST_CONFIG_KV_ID`, выполни `node scripts/create-cloudflare-deploy-config.mjs`,
затем `npx wrangler deploy --config wrangler.deploy.json`.

## 2. Собрать и установить internal

```sh
./gradlew :app:assembleInternal
```

В Windows: `.\gradlew.bat :app:assembleInternal`. APK находится в
`app/build/outputs/apk/internal/app-internal.apk`. В Android Studio выбери
build variant **internal**. Android CI также собирает APK и прикладывает artifact
`bluetooth-disable-internal` к проверке PR.

- Application ID: `com.pulse.bluetoothdisable.internal`.
- Версия имеет суффикс `-internal`, обычный значок подписан `Bluetooth Disable (Internal)`.
- Сборку можно установить рядом с обычной версией. У них раздельные локальные данные,
  заметки, галерея, коды доступа и ключи Android Keystore.
- Сборка подписана debug-ключом. Для обновлений без удаления используй один и тот же
  локальный ключ. APK разных CI-запусков может иметь разные debug-подписи и потребовать
  удаления предыдущей **internal**-установки; её локальные данные при удалении потеряются.
- Только `internal` имеет разрешение `INTERNET`. У `debug` и `release` нет клиента,
  endpoint, хранилища токена или панели тестового доступа. Разрешение сети выдаётся
  Android при установке, без отдельного запроса пользователю.

Открой главный экран internal и блок **Внутреннее тестирование**, введи `token`,
нажми **Сохранить и проверить**. Поле пароля очищается после отправки. Токен хранится
зашифрованным AES-GCM с ключом Android Keystore в `noBackupFilesDir`; в резервные
копии, перенос данных, журналы и сохранённое состояние UI он не попадает.

## 3. Включать и отзывать доступ

- Для включения измени `launcher-test.allowLauncherWithoutDeviceOwner` на `true`.
- Приложение запрашивает конфиг при входе на главный экран и по кнопкам проверки.
  На главном экране без ДО появится **Сменить значок**. Cover Mode настраивается
  существующим способом. Полная защита Bluetooth без ДО не становится доступной.
- Для общего отключения поставь флаг `false`.
- Для отдельного устройства поставь `enabled: false` у соответствующего `token:…`
  или удали эту запись. На устройстве также можно нажать **Удалить тестовый токен** —
  локальный доступ выключится сразу.

Ответ API содержит только флаг и срок, без списка устройств или хешей токенов.
Ответы имеют `Cache-Control: private, no-store`. KV распределён и имеет eventual
consistency: изменения могут появляться с задержкой, обычно порядка 60 секунд,
иногда дольше. Не обещаем мгновенный отзыв. В приложении разрешение живёт максимум
900 секунд с момента начала успешного запроса, измеряется через `elapsedRealtime`
и не продлевается при сетевой ошибке. При следующем успешном запросе с выключенным
флагом или HTTP 401/403 доступ снимается сразу. После завершения процесса старое
разрешение не восстанавливается — требуется новая проверка. Уже выбранный Cover Mode
и пользовательские данные при отзыве не сбрасываются.

HTTPS использует штатную проверку сертификата. Перенаправления запрещены, чтобы
токен не отправлялся на другой адрес. Таймаут соединения/чтения — 5 секунд,
максимальный JSON — 4096 байт. Запросы не выполняются из Cover Mode: только при
открытии основного экрана или явной проверке в нём.

## Проверки перед использованием

```sh
node --test cloudflare/worker.test.mjs scripts/create-cloudflare-deploy-config.test.mjs
./gradlew :app:testDebugUnitTest :app:testInternalUnitTest :app:lintDebug :app:lintInternal :app:assembleDebug :app:assembleInternal
```

CI дополнительно собирает release с временным ключом и проверяет реальные APK:
`INTERNET` и сетевой клиент есть только в internal, application ID и все пять
launcher-alias соответствуют выбранному пакету. Проверяется именно APK, поскольку
отдельный application ID должен сохранять работоспособность переключения иконок.

Ручная проверка:

1. Без заголовка Authorization API возвращает 401; неизвестный или отозванный токен
   также возвращает 401. API не принимает токены в URL и не позволяет менять KV.
2. При флаге `false` на internal без ДО кнопка отсутствует.
3. При флаге `true` и своём токене кнопка есть; проверь все четыре Cover Mode и возврат
   к обычному значку на своём устройстве.
4. Установи `validForSeconds: 15`, дождись распространения KV, обнови доступ и
   выключи сеть. Через 15 секунд кнопка должна скрыться, открытый выбор значка закрыться.
5. При отзыве и новой проверке кнопка скрывается. Выбранный режим и локальные данные
   сохраняются. Обычные debug/release продолжают требовать ДО для кнопки.

Из-за открытых исходников посторонний может изменить свою сборку и убрать проверку
интерфейса. Эта схема ограничивает чтение твоего серверного конфига и доступ в штатной
internal-сборке; она не запрещает людям модифицировать открытый код. Авторизованное
устройство может прочитать полученный ответ, а скопированный токен даёт тот же доступ.
